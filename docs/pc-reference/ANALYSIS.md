# PC CS 1.6 VGUI1 — визуальный анализ (задача G)

Сверка 46 эталонных скринов ПК CS 1.6 (`docs/pc-reference/*.png`) с нашей
VGUI1-реализацией. Цель — зафиксировать каноничный вид/поведение для задач
B (resize), H (picker-окна), I (правки TrackerScheme.res).

Изучены детально: настройки/мультиплеер, видео, мышь, picker цвета HUD.
Остальные скрины (вкладки сети/серверов/новой игры/аккаунта/HUD) подтверждают
те же закономерности.

## 1. Палитра (источник правды — TrackerScheme.res)

Канон ПК — тёмно-серая «стальная» гамма Source/Tracker, НЕ синий GoldSrc-фон:

- Фон диалога: тёмно-серый `~ (68,68,68)`..`(76,76,76)`, ровный, без градиента.
- Заголовок (активный титлбар): чуть светлее фона, с тонкой светлой
  верхней грань-линией (highlight) и тёмной нижней (shadow).
- Кнопки: базовый серый `~ (84,84,84)`; светлая грань сверху/слева,
  тёмная снизу/справа (классический 1px bevel «выпуклый»).
- Текст: почти белый `(216,216,216)`/`(255,255,255)`; неактивный — серее.
- Акцент/выбор: жёлто-оранжевый CS-hover на пунктах списков и при наведении
  (label hover). Выбранная строка списка — заливка приглушённым жёлтым.
- Поля ввода (text entry): фон ТЕМНЕЕ диалога `~ (40,40,40)`, «вдавленный»
  бевел (тёмная грань сверху/слева, светлая снизу/справа — инверсия кнопки).

ВЫВОД для I: проверить в TrackerScheme.res именно эти роли цветов
(Border.Bright / Border.Dark / Border.Soft, Button.BgColor,
Button.ArmedBgColor, TitleBar.BgColor, и BgColor диалога). Если фон уходит
в синий — это GoldSrc-наследие, заменить на стальной серый.

## 2. Бевелы и «глубина» (1px edges)

ПК VGUI1 строит объём ОДНОПИКСЕЛЬНЫМИ гранями, не тенями-картинками:

- Outset (кнопка, нажатая «вверх»): top+left = bright, bottom+right = dark.
- Inset (поле ввода, утопленный список/превью): top+left = dark,
  bottom+right = bright.
- Рамка диалога: двойная линия — внешняя тёмная + внутренняя светлая,
  даёт эффект «рамки в рамке».
- Разделители групп (depth lines): одиночная тёмная линия + 1px светлая
  под ней (engraved separator), используется между секциями вкладок.

ВЫВОД для B/I: при resize/зуме грани ВСЕГДА 1px (не масштабировать толщину
рамки!). Масштабируются: размер шрифта, отступы, размеры контролов — но
бевел остаётся 1px. Это ключевое для честного зума (задача B).

## 3. Вкладки (tabs) — Options как набор страниц

- Сверху ряд кнопок-вкладок (Видео / Звук / Клавиатура / Мышь / и т.д.).
  Активная вкладка «вдавлена» (inset) и её фон сливается с телом страницы
  (нет нижней грани между активной вкладкой и контентом — «приклеена»).
- Неактивные вкладки — обычные outset-кнопки, чуть темнее, с зазором сверху.
- Тело страницы — единый прямоугольный «лист» под рядом вкладок.

ВЫВОД: вкладка != обычная кнопка. Активная должна терять нижнюю грань и
совпадать по фону с листом. Сейчас проверить отрисовку tab-строки.

## 4. Анимация нажатия (press)

- Hover: текст/иконка пункта подсвечивается жёлтым; у кнопки чуть светлеет фон
  (ArmedBgColor), грани не меняются.
- Press (нажато): бевел ИНВЕРТИРУЕТСЯ (outset → inset) + контент (надпись)
  смещается на (+1,+1) пикселя вправо-вниз — эффект «вдавил».
- Release: возврат бевела и смещения.

ВЫВОД: press = swap граней + сдвиг лейбла на 1px. Без отдельных текстур.
Анимации затухания нет — мгновенное переключение состояний.

## 5. Поля ввода / списки / ползунки

- Text entry: inset, тёмный фон, мигающий курсор `|`, текст белый,
  выделение — жёлтая заливка.
- Списки (серверы, друзья, logos): inset-рамка, заголовки колонок —
  outset-кнопки (сортировка), строки чередуются? — на ПК НЕ чередуются,
  фон ровный; выбранная строка — жёлтая заливка, текст темнеет.
- Scrollbar: узкий, желоб тёмный (inset), ползунок outset-серый, стрелки
  вверх/вниз — мини-кнопки с outset-бевелом.
- Sliders (чувствительность, громкость): желоб — тонкая inset-линия,
  бегунок — маленькая outset-кнопка.
- Combo/spin: на ПК выпадающий list (combo), а НЕ циклическая стрелка.
  (важно — см. §7).

## 6. Picker цвета (выберитецветHUD / выбратьцветприцела)

Отдельное модальное окно:
- Сетка фиксированных color-swatch (квадраты палитры), каждый в 1px рамке;
  выбранный — обведён ярче/двойной рамкой.
- Превью текущего цвета (большой прямоугольник, inset).
- Поля R/G/B (числовые) + ползунки под сеткой.
- Кнопки OK / Отмена снизу, стандартные outset.

ВЫВОД: у нас уже есть `controls/ColorPicker.cpp` + `menus/ColorPickerDialog.cpp`.
Сверить: наличие сетки фикс-свотчей (а не только HSV-области), inset-превью,
R/G/B полей, и что окно модальное с OK/Cancel.

## 7. Picker-окна лого/фото (задача H) — ГЛАВНОЕ расхождение

ПК: выбор лого (spray) и аватара — это ОТКРЫВАЮЩЕЕСЯ окно со списком/сеткой
превью + кнопки OK/Отмена, иногда с прокруткой миниатюр.

У нас (`menus/PlayerSetup.cpp`): лого выбирается через `CMenuSpinControl logo`
(циклическая стрелка ◄ N ►) — это и есть «cycle-заглушка». Превью одно
(`CMenuLogoPreview`), листается по одному.

ВЫВОД для H:
1. Заменить spin-cycle на кнопку «Выбрать…», открывающую picker-диалог.
2. Picker = модальное окно: прокручиваемая сетка/список превью logos/*.png|bmp
   (модель `CLogosListModel` уже есть — переиспользовать), выбор → OK пишет
   через `WriteNewLogo()`, Cancel — откат.
3. Тот же паттерн — для фото/аватара (если есть отдельный ресурс).
4. Окно строить как ColorPickerDialog (модальный CMenuBaseWindow), а не
   inline-контрол.
